# Workbench Skills 执行协议 v2

本目录描述应用协议。独立 Skill 采用 [Agent Skills 目录与 SKILL.md 规范](https://agentskills.io/specification)：目录名与 YAML name 一致，description 说明适用条件，正文封装方法。核心 Skill 的 references/quality-checklist.md 与交付文档 assets/ 模板按需读取。

## 18 项能力，六项核心闭环

注册表在 src/lib/workbench/skills.ts；六个核心 ID 为 fde-interview-analyzer、fde-gap-finder、fde-scenario-evaluator、fde-stage-review、fde-next-action、fde-deliverable-builder。其他 12 项提供需求、阶段定位、流程、场景发现、ROI、数据、架构、方案、PoC、Agent 评测、风险和运营方法。P0/P1 是产品优先级，均已注册并可选择执行，不代表行业标准。

六个核心使用独立输出校验，其他方法使用公共结构化协议。所有执行均为模型辅助分析，不会自动调用 ERP、运行脚本或替企业完成业务任务。

## 应用层六项字段

这些字段属于本应用，不是 Agent Skills 标准 frontmatter。

| 字段              | 实现                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| trigger           | 注册表中的事件和适用条件，配合 planSkills 路由规则                    |
| input_schema      | 版本化上下文名称；实际 Zod 定义在 protocol.ts                         |
| output_schema     | 公共或专用输出名称；outputSchemaFor 返回实际校验规则                  |
| quality_gate      | 引用、Schema、项目范围、阶段规则与审批检查                            |
| requires_approval | 所有状态变更建议都需人工确认；AI 提取只产生待核实事实、开放问题或草稿 |
| project_effect    | 能提出的事实、问题、任务、阶段建议或文档版本                          |

GET /api/workbench/skills/<id> 返回方法正文、应用协议以及可机器读取的 input/output JSON Schema。旧版四个 Skill ID 仍可解析到新 ID，历史项目记录无需重建。

## 依赖执行

1. 根据输入执行访谈分析或需求理解。
2. 根据关键词、阶段或人工选择执行专业分析（自动最多两项；手动最多三项）。
3. 识别信息缺口；已有 AI 场景时并行评估五个维度。
4. 逐项检查当前阶段，叠加真实门禁规则。
5. 下一步规划读取全部已完成的前序结果，以及已有任务与项目记忆。
6. FDE 核实事实、编辑确认行动，生成任务；可同时申请行动计划草稿。
7. 交付资产 Skill 使用审批、已确认分析、事实和文档模板生成正文。生成后的草稿仍需人工审核。

同一轮 phase 按序执行，同阶段互不依赖的 Skill 可并行。每个步骤有 queued/running/completed/failed/skipped 状态。前序失败后依赖步骤不调用模型；整轮不产生可批准的判断。阶段检查结果不能写阶段完成状态。

## 质量门禁

- 事实与责任人引用需在项目原始资料中逐字匹配。新事实始终是 proposed。
- 问题必须包含 topic、question、why、askWho、priority、sourceIds；引用只能指向当前项目，已有问题可通过 issueId 合并。
- 场景按业务价值、技术难度、数据就绪、组织阻力、风险做 1–5 序数判断。缺证据必须为 null，不生成无依据总分或 ROI。
- 阶段检查必须覆盖当前阶段全部真实 criterionId。资料支持不代表人工门禁已通过；引擎阻塞项优先。
- 行动记录优先级、前置条件、建议角色、注册 Skill 和已有任务依赖。依赖未完成时不能开始或完成后续任务。
- 文档必须引用有效 sourceIds 和 decisionIds，并包含本次 approval.id。未经审核的草稿不能用于门禁、关闭问题或完成任务。

## 五类持续项目数据

事实、开放问题、阶段与任务、决策、资产共同持久化于项目 JSON。问题按 issueId 或规范化问题文本合并；语义相近但措辞不同的缺口依赖模型复用已有 issueId，不宣称具备通用语义去重能力。已关闭问题保留核实证据与历史，模型不自动重新打开。AI 可提高开放问题的优先级，降低已有 P0 阻塞项的优先级需要人工决定。

任务完成触发下一轮规划，使用真实模型额度；当前已有分析时合并为待复查标记，运行结束后执行。确认人通过明确的命令提交审计理由。重新打开依赖任务、撤回事实证据或重新打开已完成阶段的 P0 问题时，相关下游完成审批失效。

文档支持访谈纪要、项目诊断表、场景评估报告、AI 落地方案、阶段验收报告、行动计划。生成与人工修订均追加版本，不覆盖历史。修订稿需要重新审核；旧的已审版本继续保留。

## 运行边界

单 Node 进程、本地持久化文件、可信用户。Next.js after 执行后台调用，单次模型请求超时 90 秒，整轮分析超过 10 分钟标记失败并可重试；没有跨实例的持久化 Worker。服务重启不会自动重新执行被中断的模型调用。文件写入原子化并检查修订号。密钥通过现有服务端配置读取，不进入项目上下文或导出文档。

## 后续行业包

制造、服装纺织、营销获客、企业经营、教育培训、外贸出海是后续路线，当前没有冒充已实现的行业包。扩展时复用通用访谈/追问/ROI，通过新 SKILL.md 和 references 提供行业约束、指标口径和专项问题；将新 ID、路由条件、Schema 与质量门禁加入注册表，再补充项目证据与失败路径验证。
