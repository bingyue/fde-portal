# 项目阶段判断

## 标准输入
当前项目、原始资料、已确认事实、开放问题、前序分析、任务与证据标准。

## 适用条件
询问项目进度或导入资料。

## 执行步骤
1. 按项目输入区分已经发生的交付活动与客户计划。
2. 对照九阶段的最早未满足条件，定位实际工作进度。
3. 分别给出当前登记阶段、资料反映的成熟度、建议关注阶段与证据。
4. 存在跨阶段材料时说明并行工作，不自动跳跃地图。

## 输出结构
遵循应用 skill-result.v2：summary、facts、missing、contradictions、recommendation、suggestedStage、actions、deliverables。事实必须含 sourceId、逐字 quote。actions 给出负责人角色、阶段和是否阻塞；交付文档待人工确认后由专门 Skill 生成。

## 质量检查
每项结论区分事实、假设和建议。数值与完成状态可追溯；不虚构已连接ERP/MES、已测试、已上线或已获授权。不重复已有任务。

## 终止条件
关键数据或业务边界不清楚时停止确定性结论，输出核实动作。不能自动修改阶段或执行外部业务写入。
